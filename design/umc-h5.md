# OctopusUMC — H5 移动端功能规格

## 概述

OctopusUMC 是统一用户中心（身份提供商 IdP）。

**H5 移动端定位**：UMC 的管理后台（用户/角色/菜单/部门管理）属于**管理员操作**，不适合移动端。
因此 UMC H5 的核心场景只有两个：

1. **SSO 登录页**：作为 OA/PLM/CRM 等系统 SSO 的统一登录入口，手机端也需要美观可用
2. **个人资料页**：用户修改自己的密码、头像、手机号

## 页面清单

### 1. SSO 登录页（最核心）

这是手机用户打开任何 OctopusERP 子系统时都会看到的页面，重要性最高。

#### 布局

```
┌─────────────────────────────┐
│  （状态栏）                  │
│                              │
│                              │
│       🐙                    │  Logo，64px
│    OctopusERP               │  品牌名，20px 600
│    企业数字化平台              │  副标题，13px muted
│                              │
│  ─────────────────────────  │  分割线（可选）
│                              │
│  用户名                      │  Label，12px
│  [________________]          │  Input，h-12
│                              │
│  密码                        │
│  [______________ 👁]         │  Input，末尾切换显示密码
│                              │
│                              │
│  [        登 录        ]     │  全宽主按钮，h-12
│                              │
│  忘记密码？                  │  居中，14px，primary 色
│                              │
│                              │
│  © 2025 OctopusERP          │  底部版权，11px muted，居中
└─────────────────────────────┘
```

#### 交互细节

- 手机号/用户名输入框：`type="text"` `autocomplete="username"`
- 密码框：`type="password"` `autocomplete="current-password"` + 末尾眼睛图标切换明文
- 登录按钮 loading 态：显示转圈，禁止重复提交
- 错误提示：按钮下方红色提示文字（不用弹窗）
  - 账号或密码错误
  - 账号已被禁用，请联系管理员
- 登录成功：`window.location.href` 跳回 OIDC `returnUrl`（OpenIddict 授权码流）

#### 状态判断

UMC 前端登录页检测 `returnUrl` 参数：

```
URL 带 returnUrl=/connect/authorize?...
  → 登录成功后 window.location.href = returnUrl  （走 OIDC 流程，回到 OA/PLM）

URL 不带 returnUrl
  → 登录成功后跳到 UMC 后台首页 /dashboard
    （直接访问 UMC 的管理员）
```

#### 数据接口

```
POST /api/account/login
Body: { userName, password }
Success: Set-Cookie (HttpOnly), 返回用户基本信息
Error 401: 账号或密码错误
Error 403: 账号已禁用
```

## 不需要在 H5 实现的功能

UMC 核心是管理后台，以下功能**仅桌面端**：

| 功能模块 | 原因 |
|---|---|
| 用户管理（CRUD） | 管理员操作，表格复杂，需宽屏 |
| 部门/机构管理 | 树形结构，手机操作体验差 |
| 角色/菜单管理 | 配置项多，不适合移动端 |
| 字典管理 | 管理员配置，低频 |
| OIDC 客户端管理 | 纯技术配置 |
| 操作日志/在线用户 | 表格展示为主 |

## UMC H5 路由结构

```
/login        → SSO 登录页（最核心）
/callback     → OIDC 回调（自动跳转，无 UI）
/profile      → 个人资料
/profile/pwd  → 修改密码
```

---

## 与 OA H5 的关系

```
用户打开 OA H5（手机）
  → OA 检测未登录
  → 跳转到 UMC H5 /login?returnUrl=/connect/authorize?...
  → 用户在 UMC H5 登录页完成登录
  → UMC 跳回 /connect/authorize（已有 Cookie）
  → OpenIddict 颁发授权码
  → 跳回 OA H5 /callback
  → OA H5 正常使用
```

因此 **UMC H5 登录页的体验直接影响所有子系统的登录转化率**，这是最关键的页面。
