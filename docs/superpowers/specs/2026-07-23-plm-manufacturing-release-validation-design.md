# PLM 制造版本发布校验设计

## 目标

让用户在发布制造版本前立即知道哪些真实制造资料缺失，避免按钮无反馈、仅弹出短暂提示，或把空 BOM、空工艺路线同步到 MES。

## 状态与交互

- 草稿资料完整时，状态显示“草稿”，操作显示“发布制造版本”。
- 草稿资料不完整时，状态显示红色“资料不完整”，并在表格中用红色文字列出缺失项摘要；操作显示“补齐发布资料”。
- 点击“补齐发布资料”直接打开该草稿的编辑区。
- 编辑区中有问题的输入框显示红色边框，字段下方显示具体红色错误文字。
- 保存草稿允许资料暂时不完整，但必须保留并显示校验结果。
- 发布前必须重新校验；存在任何错误时不得进入二次确认，也不得调用发布接口。
- 校验通过后，第一次点击进入“再次点击确认发布”，第二次点击发布 PLM 制造版本并通知 MES。

## 必填规则

### BOM

- 至少一条 BOM 明细。
- 每条明细必须有物料编码。
- 每条明细必须有物料名称。
- 用量必须大于 0。
- 损耗率不得小于 0。

### 工艺路线

- 至少一道工序。
- 每道工序必须有工序编码。
- 每道工序必须有工序名称。
- 每道工序必须有能力编码。
- 标准工时必须大于 0。
- 换型时间不得小于 0。

## 前后端职责

- PLM API 是最终校验边界，创建、修改可保存草稿，发布接口必须拒绝不完整资料并返回结构化缺失项。
- PLM 列表接口返回每个版本的发布就绪状态和缺失项摘要，确保刷新页面后仍能看到问题。
- 前端复用同一组字段规则提供即时反馈，但不得替代后端校验。
- MES 只接收已经通过 PLM 发布校验的制造版本，不接收不完整草稿。

## 错误呈现

- 字段级错误紧邻输入框显示，不能只依赖消息提示。
- 表格级摘要使用红色文字，最多展示主要缺失项，其余以数量补充。
- 接口、登录或网络错误使用明确消息提示，按钮恢复可点击状态，不得静默失败。

## 验收标准

1. 当前空数据 V1.0 在列表中显示红色“资料不完整”和实际缺失项。
2. 点击操作按钮会打开编辑区，空物料编码、物料名称、工序编码、工序名称、能力编码均出现红色标识。
3. 未补齐资料时不能发布，PLM 仍为草稿，MES 不产生同步事件。
4. 补齐并保存真实资料后，红色错误消失，按钮变为“发布制造版本”。
5. 二次确认发布成功后，PLM 显示“已发布”，MES 显示“已同步”或明确的同步失败原因。
6. 页面刷新后，校验状态与错误摘要保持一致。

## 测试

- API 测试覆盖每项 BOM、工序必填规则和合法发布路径。
- 前端构建与类型检查覆盖模板和类型错误。
- 运行态验收覆盖空草稿、补齐草稿、发布、MES 接收四个阶段。
