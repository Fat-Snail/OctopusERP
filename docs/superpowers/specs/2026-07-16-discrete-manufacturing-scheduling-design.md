# 离散制造通用排程设计

## 目标

将当前 MES 中面向服装的“生产小组 × 日期”排程，演进为适用于装配、机加工、电子、服装等离散制造场景的工序级排程，同时保留现有服装数据和页面的兼容能力。

核心链路为：

```text
生产需求 → 生产订单 → 工艺路线 → 工序任务 → 工作中心/资源 → 时间段排程 → 派工与报工
```

默认排程目标为交期优先，但通过可配置权重支持不同工厂在交期、产能利用率、换型成本和订单优先级之间调整取舍。

## 现状与兼容边界

当前模型包含 `MesWorkOrder`、`MesWorkOrderProcess`、`MesEquipment`、`MesGarmentTeam`、`MesGarmentOrder` 和 `MesGarmentSchedule`。其中 `MesGarmentSchedule` 将排程固定为 `TeamId + ScheduleDate`，适合服装日计划但无法表达设备级工序、班次、前置关系和分钟级时间段。

第一阶段不删除旧表。通用模型作为新主模型，旧服装排程通过兼容映射继续读写：服装小组映射为一种 `生产资源`，日排程映射为一个按天聚合的排程视图；现有 API 在迁移期间保持可用。

## 领域模型

### 主数据

- `MesProduct`：可生产产品及版本。
- `MesBom`、`MesBomItem`：产品、组件、数量、损耗和替代料关系。
- `MesRouting`、`MesRoutingOperation`：工艺路线、工序顺序、标准工时、批量、替代工序和返工关系。
- `MesWorkCenter`：生产区域或能力集合，例如车间、产线、装配单元。
- `MesResource`：设备、人工班组或外协供应商；包含能力、状态和所属工作中心。
- `MesResourceCalendar`、`MesShift`：班次、工作日、休息、维护和停机时间。

### 交易与执行

- `MesProductionOrder`：生产数量、交期、优先级、产品版本、来源订单和状态。
- `MesOperationTask`：生产订单拆分出的工序任务，记录前置任务、数量、标准工时、状态和实际执行数据。
- `MesSchedulePlan`：排程版本，支持草稿、模拟、发布、冻结和归档。
- `MesScheduleSlot`：工序任务在具体资源上的开始时间、结束时间、数量和排程来源。
- `MesDispatchOrder`：面向现场的派工指令，关联工序任务和资源。
- `MesOperationReport`：开工、暂停、报工、良品、不良、返工、停机原因和实际工时。

状态流转统一采用显式状态机，禁止 Controller 直接修改任意状态：

```text
草稿 → 已计划 → 已发布 → 已派工 → 生产中 → 部分完成 → 已完成
                                  └→ 暂停/返工/取消
```

## 排程规则

### 必须满足的硬约束

1. 工序前置关系：后置工序不能早于前置工序完成或允许的重叠点。
2. 资源能力：资源必须具备工序所需能力，且处于可用状态。
3. 资源不重叠：同一资源在同一时间不能安排冲突任务。
4. 资源日历：排程时间只能落在班次可用区间内，自动跳过维护、停机和节假日。
5. 数量一致：工序任务数量不能超过可生产数量，拆分任务数量之和必须可追溯。
6. 冻结保护：已开工任务和冻结区间内的任务不能被自动重排。

### 可配置软约束

- 交期紧迫度。
- 订单优先级和客户等级。
- 资源利用率。
- 换型时间和换型次数。
- 同产品/同批次连续生产。
- 外协成本和运输缓冲。
- 工序等待时间和在制品上限。

默认策略使用“交期优先 + 最早可用资源 + 工序前置约束”。排程器通过 `ISchedulingStrategy` 抽象策略，后续可以增加产能优先、换型优先或 OR-Tools 优化策略，不改动 API 和数据库边界。

## 排程服务边界

`SchedulingService` 只负责生成候选排程、解释冲突和保存排程版本，不直接处理现场报工。建议拆分以下接口：

- `IOrderExploder`：生产订单按工艺路线展开为工序任务。
- `IResourceCalendar`：查询资源可用时间段。
- `ICapacityCalculator`：计算标准工时和数量对应的占用时长。
- `ISchedulingStrategy`：按权重生成候选顺序和资源选择。
- `IConflictDetector`：报告资源冲突、前置冲突、物料不足和交期风险。
- `IDispatchService`：将已发布排程转换为现场派工。

返回结果必须同时包含排程和解释信息：哪些任务被安排、哪些任务无法安排、冲突原因、预计延期时长以及受影响的资源。

## API 与前端规划

新增通用 API：

- 生产订单与工艺路线查询。
- 工序任务展开和资源候选查询。
- 创建/模拟/发布/冻结/重排排程版本。
- 甘特图数据、工作中心负载、资源日历和冲突列表。
- 派工、开工、暂停、报工、返工和完工。

现有服装 API 保留，并由兼容适配器读写通用排程；前端先增加通用甘特图和资源负载视图，再逐步将服装日历切换为通用数据源。

## 数据迁移策略

1. 新增通用表，不改动旧服装表的既有字段。
2. 为现有 `MesGarmentTeam` 创建对应资源和工作中心映射。
3. 将历史 `MesGarmentSchedule` 以只读兼容视图映射到 `MesScheduleSlot` 的天级聚合。
4. 新建排程默认写入通用模型；兼容 API 在事务内同步旧表摘要字段。
5. 稳定运行后，将旧接口标记为兼容接口，最后再评估归档旧表。

## 实施阶段

1. 建立主数据和领域状态机，补齐实体、索引、迁移和测试。
2. 实现订单展开、资源日历、能力计算和硬约束冲突检测。
3. 实现默认规则排程、排程版本、模拟/发布/冻结/重排。
4. 将服装排程接入兼容适配器，验证历史数据和现有前端行为。
5. 增加甘特图、负载分析、延期预警和现场派工。
6. 打通 PLM、CRM、WMS、FIN、HRM 的订单、物料、成本和工时事件。
7. 根据真实工厂数据增加可配置策略和高级优化器。

每个阶段遵循 TDD：先为领域规则和状态流转写失败测试，再实现最小逻辑；关键路径使用 SQLite 集成测试覆盖。

## 验收标准

- 同一资源不存在重叠排程。
- 后置工序不会早于前置工序。
- 维护、休息和冻结区间不会被安排任务。
- 交期、资源利用率和换型权重改变时，排程结果可解释且可复现。
- 服装旧 API 和历史数据继续可读，兼容写入不会破坏新模型。
- 每个排程版本可以查看生成规则、冲突和变更记录。
- 生产订单、工序任务、排程、派工和报工之间全链路可追溯。
